# CI diet — 23 October 2026

PR body notes for `ci/diet-2310`. No PR is opened by this change.

## Commit A — safe infrastructure and test changes

- All three Tauri prerequisite steps use one local composite action with a
  five-minute step timeout. Apt's update/download phase gets two bounded
  110-second attempts, a 15-second backoff, two transport retries and 15-second
  HTTP/HTTPS timeouts. Installation runs only after a complete download and
  uses `--no-download`. After authenticated index refresh, restored debs are
  explicitly checked against the exact package/version/architecture, SHA256 and
  size from apt metadata; unrecognized, stale or corrupt entries are discarded.
  Apt verifies new downloads. This avoids apt's size-only cached-file shortcut.
- Cache only `.deb` files, keyed by runner OS, architecture, image version and
  installer/verifier hash. `actions/cache` v4.2.3 is pinned to
  `5a3ec84eff668545956fd18022155c47e93e2684` (verified against the upstream tag).
  No cached filesystem extraction, unsigned repositories or secrets are used.
- Sidecar keeps its complete fetch, signature/checksum verification, config
  drift, owner lifecycle, CS-1 and CS-2 behavior. PRs run it for `full-ci` or
  sidecar-related paths; main pushes, version tags and merge groups still run
  it after Build succeeds. Classification failure remains fail-closed.
  The filter conservatively includes all `src-tauri/**` because the sidecar
  exercises the host crate, plus fetch/verification/smoke scripts and CI helpers.
  Existing label semantics stay unchanged: `full-ci` is read on the next PR
  synchronization, not on a `merge-ready` labeling event. The inexpensive CS-2
  renderer/host security checks also run in Build on every code PR, so scoping
  Sidecar never removes their frontend coverage.
- Disk cleanup checks for 12 GiB free before deleting unused toolchains, stops
  once that floor is reached, and never deletes Android. This is a conservative
  starting threshold, not a measured disk guarantee: the existing workflow
  records a prior linker disk-full failure. Retain the final disk diagnostics
  and inspect the first hosted runs before changing the threshold.
- The three slow UI suites advance virtual time through the real polling,
  expiry and queue logic. All 266 tests and their assertions remain. Explicit
  sleeps advance the same durations; polling keeps its 50-ms interval and
  original deadlines. FileReader cases retain real timers because Happy DOM
  owns their separate timer queue. Each suite disposes the app before restoring
  real timers; no production timing, test selection, isolation or coverage gate
  changes.
- `webkit.yml` from #331 is **absent** from freshly fetched `origin/main`
  (`5bdabbe1add0f99d4fa169e83675d9bbb7564625`). No WebKit workflow/check is
  invented or removed. Atlas's non-UI in-job early-success path remains to be
  added when that workflow lands; do not use a workflow-level paths filter for
  a required check.

Authority Check, Build on every main push, Android checks, Dependency Audit,
release workflows and all signature checks retain their coverage. Workflow
permissions retain `contents: read` and the existing classifier-only
`pull-requests: read`; no secret is added. No `cargo fmt` was run.

## Commit B — Atlas approved: PR coverage plus changed-main nightly

Atlas approved B in modified form: Starter balance enabled runs on every PR
touching its existing code paths, on the `full-ci` override, and nightly on
main when its SHA differs from the last successful scheduled run. Version
tags, merge groups and fail-closed PR classification retain their coverage.
The existing `full-ci` label timing described above is unchanged. Build still
compiles every push to main; Starter no longer repeats on every main push.

`starter-balance-nightly.yml` runs daily at **03:00 UTC** and supports
`workflow_dispatch` on main to force verification even when unchanged. Other
refs are skipped. The schedule becomes active once the workflow lands on main
(the repository's default branch).

- Before any checkout, a two-minute gate uses `gh api` with `GITHUB_TOKEN` to
  read this workflow's most recent successful `schedule` run on main. The query
  is scoped to the dedicated Starter workflow, so successes from Build, PRs or
  manual runs cannot suppress a nightly. Only this gate gets `actions: read`;
  the workflow and build otherwise have `contents: read` only.
- Compare that run's `head_sha` with `github.sha`, main's HEAD captured for the
  scheduled event. The build checks out that exact SHA, avoiding a race if main
  advances during startup. An equal SHA skips all checkout/build/test work;
  no prior success or a different SHA runs the full existing Starter frontend
  build/tests and Rust tests with `VITE_STARTER_BALANCE=1`.
- An unchanged successful no-op preserves the same already-green SHA. Failed
  or cancelled runs never advance the last-green SHA; changed main is retried
  on the next night. API failures also fail the workflow. No errors are
  swallowed: **a red nightly is P0 under Atlas's policy**. Manual verification
  does not update the scheduled baseline. Runs do not cancel an active nightly.
- Every external action in the new workflow is pinned to a verified commit
  SHA; the local apt composite already pins its cache action. No write
  permission or new secret is introduced.

B remains a revertable pair: original commit `7faa5ef` drops the main-push run,
and its follow-up adds this nightly replacement and final policy documentation.
Revert the follow-up first, then `7faa5ef`, to restore Starter on every main
push without losing any of commit A.
